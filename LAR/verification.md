# Verification Artifacts

**Produced by:** Agent C (Verification Engineer)  
**Independence:** Agent C is on the developer side of the independence line; DO-178C independence comes from the human reviewer at the commit gate, who reviews this verification record. Agent C is blind to Agents A and B's reasoning (anti-anchoring): it receives only formal artifacts — never reasoning or internal deliberation from development agents. If the artifact doesn't demonstrate compliance, it doesn't comply.

---

## test_cases/system/ — TC-SYS-XXXX

System-level test cases written against SYS requirements. Verify that the integrated software meets the top-level operational requirements including failure detection and timing.

**File:** `TC-SYS-XXXX-YY.yaml`

```yaml
id: TC-SYS-XXXX-YY
title: [technique — brief description]
requirement: SYS-XXXX
test_level: system
technique: [normal | boundary | equivalence | state_transition | abnormal | failure_condition]
preconditions:
  - [specific system state]
inputs:
  - parameter:
    value:
    unit:
expected_results:
  - parameter:
    value:
    rationale: >
      [traced to requirement text]
pass_fail_criteria: >
  PASS if [specific measurable condition].
  FAIL if [specific measurable condition].
status: draft
```

## test_cases/hlr/ — TC-HLR-XXXX

Integration test cases written against HLR. Written **before Agent B writes code**. The act of writing these tests is the primary mechanism for discovering requirement gaps — when Agent C cannot determine expected behavior for a condition, it generates a Problem Report rather than assuming behavior.

**File:** `TC-HLR-XXXX-YY.yaml` (same format as system test cases above)

## test_cases/llr/ — TC-LLR-XXXX

Executable unit test cases written against LLR. These are the tests Agent B must pass. Implemented as pytest test functions with requirement traceability markers.

**File:** `TC-LLR-XXXX-YY.yaml` (YAML spec) + corresponding pytest function in `test_procedures/`

## test_procedures/

Executable implementations of test cases. Python/pytest files. Each test function must include:

```python
@pytest.mark.requirement("LLR-XXXX-YYY")
@pytest.mark.test_id("TC-LLR-XXXX-YY")
def test_[description]():
    """
    Requirement: LLR-XXXX-YYY — [requirement title]
    Inputs: [parameter] = [specific value] [unit]
    Expected: [parameter] == [specific value]
    Pass if: [measurable condition]
    Fail if: [measurable condition]
    """
    # arrange
    # act
    # assert with specific values, not vague conditions
```
