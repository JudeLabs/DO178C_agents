## baselines/

Immutable snapshots at each lifecycle milestone. Once a baseline is established, no included artifact may be modified without a formal Change Request.

**File:** `BL-[type]-XXXX.yaml`

```yaml
baseline_id: BL-[type]-XXXX
baseline_type: [planning | requirements | design | code | product]
date:
human_authorization: [gate approval record reference]
included_artifacts:
  - artifact_id:
    version:
    file_path:
    status: approved
open_problem_reports:
  deferred:
    - pr_id:
      justification: >
  count_closed:
environment:
  compiler:
  compiler_version:
  compiler_flags:
  os:
  target_hardware:
  test_tools:
```

## change_requests/ — CR-XXXX

Formal records of every proposed change to a baselined artifact. Every CR includes an impact analysis identifying all upstream and downstream artifacts affected.

**Lifecycle:** OPEN → ANALYZED → APPROVED → IMPLEMENTED → VERIFIED → CLOSED

**File:** `CR-XXXX.yaml`

```yaml
id: CR-XXXX
date_opened:
requested_by: [Agent A | Agent B | Agent C | Agent D | Human]
change_target: [artifact ID]
change_description: >
priority: [critical | high | medium | low]
status: open
impact_analysis: CR-XXXX-impact.yaml
upstream_impact: []
downstream_impact:
  requirements: []
  design: []
  code: []
  tests:
    must_update: []
    must_rerun: []
baselines_affected: []
human_approval:
  approver:
  date:
  decision: [approved | rejected]
history:
  - date:
    action:
    by:
```

## problem_reports/ — PR-XXXX

Formal defect records generated by Agent C during reviews, test-writing, and coverage analysis. The most common source is the Test Case Generator finding a requirement gap — Agent C cannot determine expected behavior and issues a PR rather than assuming.

**Lifecycle:** OPEN → ANALYZED → CORRECTED → VERIFIED → CLOSED

**File:** `PR-XXXX.yaml`

```yaml
id: PR-XXXX
date_opened:
source: [Test Case Generator | Review | Coverage Analysis | Test Failure]
finding: >
  [specific deficiency — what is missing or wrong]
affected_artifact: [artifact ID]
severity: [major | minor]
recommended_action: >
responsible_agent: [Agent A | Agent B | Agent C | Agent D]
correction: >
  [what was changed to address the finding]
verification: >
  [how Agent C confirmed the correction was effective]
status: [open | corrected | verified | closed]
```

## audit_records/ — AU-XXXX

Process compliance audit records generated by Agent D at each phase transition.

**File:** `AU-XXXX.yaml`

```yaml
audit_id: AU-XXXX
date:
auditor: Agent D
scope: >
  [which phase, which plan, which activities]
findings:
  - process_step:
    result: [conforming | nonconforming | observation | n/a]
    evidence_examined: >
    finding: >
    ncr: [NCR-XXXX if nonconforming]
summary: >
recommendation: [approve transition | hold — resolve NCRs first]
```
